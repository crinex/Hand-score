# Hexagon Artifact Setup

The repository does not commit APKs, build outputs, model binaries, or Qualcomm SDK files. That does not mean a verifier has nothing to run:

- APKs and build outputs are generated from source with Gradle / Android Studio.
- Android SDK packages are installed by Android Studio or command-line SDK Manager.
- Qualcomm runtime files and converted model artifacts are downloaded from their upstream providers after accepting their license terms.
- Raw result JSON files are generated by the app and then pulled from the device.

This file records the artifact flow that makes the source project reproducible without Git LFS.

---

## 1. Clone and build from source

```bash
git clone https://github.com/crinex/Hand-score.git
cd Hand-score/HAND-Score-Hexagon
./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

If Gradle cannot find the Android SDK, either open the project in Android Studio once or write `local.properties`:

```properties
sdk.dir=/absolute/path/to/Android/sdk
```

The helper can create this file:

```bash
python3 tools/prepare_artifacts.py init --android-sdk /absolute/path/to/Android/sdk
```

---

## 2. Download Qualcomm runtime artifacts locally

Download the Qualcomm AI Engine Direct SDK / QNN SDK from Qualcomm Developer:

```text
https://www.qualcomm.com/developer/software/qualcomm-ai-engine-direct-sdk
```

The SDK download is license-gated, so this repository cannot fetch or redistribute it automatically. After download, unpack it outside Git or under the ignored local artifact folder:

```text
HAND-Score-Hexagon/artifacts/qnn/<qairt-or-qnn-version>/
```

Register the local path for verifier notes:

```bash
python3 tools/prepare_artifacts.py init \
  --qnn-sdk HAND-Score-Hexagon/artifacts/qnn/<qairt-or-qnn-version>
```

---

## 3. Download or compile model artifacts

For exact paper reproduction, the verifier needs the same model family, quantization, tokenizer, target SoC, and QNN / Genie artifact format used by the Hexagon backend.

Recommended upstream paths:

- Qualcomm AI Hub Workbench / AI Hub Models for QNN-ready Android exports:
  - `https://app.aihub.qualcomm.com/docs/hub/`
  - `https://github.com/qualcomm/ai-hub-models`
- The original model provider or Hugging Face repository for license-controlled base weights.
- A project release or external artifact bundle if the paper authors publish checksummed converted artifacts.

A source repository should not commit these binaries. Instead, keep a local layout like:

```text
HAND-Score-Hexagon/artifacts/models/
├── Hexagon-Llama-3.2-1B/
│   ├── tokenizer files
│   ├── QNN / Genie config files
│   └── QNN model libraries, context binaries, or DLC files
├── Hexagon-Llama-3.2-3B/
└── Hexagon-Qwen3-4B/
```

Then push the chosen model directory to the app-specific device model folder:

```bash
python3 tools/prepare_artifacts.py push-model --name Hexagon-Llama-3.2-1B
```

Equivalent raw ADB command:

```bash
adb shell mkdir -p /sdcard/Android/data/com.handscore.hexagon/files/models
adb push HAND-Score-Hexagon/artifacts/models/Hexagon-Llama-3.2-1B \
  /sdcard/Android/data/com.handscore.hexagon/files/models/
```

The default benchmark options look for:

```text
/sdcard/Android/data/com.handscore.hexagon/files/models/Hexagon-Llama-3.2-1B
```

## 4. Connect a real Hexagon backend

The committed `ReferenceBackend` is a schema and workflow verifier only. It does not measure Hexagon performance.

To reproduce the paper's Hexagon numbers, implement `InferenceBackend` using the downloaded Qualcomm runtime and model artifacts, then update `BackendFactory.create(...)`:

```java
public final class BackendFactory {
    public static InferenceBackend create(Context context) {
        return new QnnHexagonBackend(context);
    }
}
```

The backend must return:

- exact tokenizer prompt counts
- model load time
- TTFT
- prefill throughput using `N_prompt / TTFT`
- decode throughput
- total time
- generated text
- `npuProfile` with Hexagon / GPU / CPU op placement counts

---

## 5. Run the protocol and retrieve results

In the app, run:

- `Run Exp A`
- `Run Exp C`
- `Run Exp E`

Or run `Run All`.

Pull JSON results:

```bash
adb pull /sdcard/Android/data/com.handscore.hexagon/files/HAND-Score ../samples/results/raw
```

Regenerate summaries:

```bash
cd ../samples/results/analysis
python3 build_summary.py
```

The analysis script accepts both iOS `aneProfile` and Android `npuProfile` result fields.

---

## What must be published for third-party reproduction?

For a third party to reproduce the exact paper numbers, the project needs one of these:

- public, checksummed converted model artifacts in a release or external artifact store; or
- exact conversion scripts plus pinned upstream model revisions and QNN / AI Hub versions; or
- a documented private artifact request process for license-restricted binaries.

Without one of those, reviewers can verify the Android project, protocol, JSON schema, and aggregation pipeline, but they cannot independently reproduce the paper's Hexagon measurements.
